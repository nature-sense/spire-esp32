# AXP2101 — protocol facts

Part number `axp2101` (AXP2101). The **AXP2101** is an XPowers power-management IC on I²C — the
rails, the charging and the battery gauge. Its address is the board's (`0x34`); the register map
below is the AXP2101's.

Derived from `spire-idf` `components/axp2101/src/axp2101.cpp` (the driver's own map, off the
datasheet). This is an **implementation, not the datasheet**: confirm the electricals against it.

## Registers

One address byte, then the value, in **one** `write_read` exchange.

- `0x00` `STATUS1` — bit 3 = battery present (bit 4 = batfet, 2 = active mode, 1 = thermal,
  0 = input current limited)
- `0x01` `STATUS2` — bits 7:5 = current direction: `0x00` standby, `0x01` charging, `0x02` discharging
- `0x03` `IC_TYPE` — the part's identity: `0x4A` is an AXP2101 and nothing else is; `probe()` checks it
- `0x30` `ADC_CHANNEL_CTRL` — bit 0 = battery-voltage measurement enabled (not read by this driver)
- `0x34` / `0x35` — battery voltage, **high byte then low byte**, adjacent; only bits 4:0 of the high
  byte are the value's top bits: `millivolts = (high & 0x1F) << 8 | low`
- `0xA4` — battery percent, the part's own gauge, 0..100

The ADC hands a measurement over as two adjacent bytes and the address pointer auto-increments, so
both halves come back in **one** exchange; two separate reads could straddle a conversion. The upper
bits of the high byte belong to the part, not the number — reading them would report a battery several
volts too high, which looks like a wiring fault on a bench.

## Probing

`probe()` reads `0x03` and requires `0x4A`. It is **identity, not presence**: a different XPowers part
answering at the address reads false rather than being taken for an AXP2101.

## What this driver does not do

It is the **reading** half only. Nothing here is written: what a board's power tree looks like is the
board's decision, so the rails, the charging and the gauge are fetched and decoded, never configured.

## What a bad reply looks like

- the bus refuses an exchange → `false`, for every read.
- `0x03` answers a byte that is not `0x4A` → `probe()` is `false` (a different part, not an absent one).
