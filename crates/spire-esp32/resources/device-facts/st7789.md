# ST7789 — protocol facts

Part number `st7789`. The **ST7789** is an SPI colour-LCD panel controller: 240 × 320, portrait, spoken
to as a MIPI DCS peripheral — one 8-bit command, then its parameters or pixels, through this
component's `bus_command` / `bus_data` seam, never a register read. The command words, the sequence and
the window a flush writes into are below.

Derived from the vendored LVGL MIPI driver (`lvgl/upstream/…/mipi/{lv_st7789,lv_lcd_generic_mipi}.c`;
init table from LovyanGFX) and this component's header — an **implementation, not the datasheet**; the
glass's datasheet is the authority.

## The command set

- `0x01` `SWRESET` — software reset (the reset *line* is the board's)
- `0x10` `SLPIN` / `0x11` `SLPOUT` — an ST7789 powers up **asleep**: without `SLPOUT` nothing is drawn
- `0x13` `NORON` — normal mode: the whole screen, no partial area, no scrolling
- `0x20` `INVOFF` / `0x21` `INVON` — colour inversion; needed by a complement-rendering panel
- `0x28` `DISPOFF` / `0x29` `DISPON`
- `0x2A` `CASET` / `0x2B` `PASET` — the ST7789's window: two corners each, **high byte first**, both
  *inclusive*
- `0x2C` `RAMWR` — write pixels into that window
- `0x36` `MADCTL` — address mode; `0x3A` `COLMOD` — pixel format

## The power-on sequence

Vendored order: `SLPIN`, 10 ms; `SWRESET`, 200 ms; `SLPOUT`, 300 ms (the pump needs the waits);
`NORON`; `MADCTL`, `COLMOD`, `DISPON`.

Then the ST7789's tuning, which no scaffold can invent:

- `GCTRL` `0xB7` = `0x44`; `VCOMS` `0xBB` = `0x24`; `VRHS` `0xC3` = `0x13`
- `PWCTRL1` `0xD0` = `A4 A1`; `RAMCTRL` `0xB0` = `00 C0` (how RGB565 widens into RGB666 memory)
- `PVGAMCTRL` `0xE0` = `D0 00 02 07 0A 28 32 44 42 06 0E 12 14 17`
- `NVGAMCTRL` `0xE1` = `D0 00 02 07 0A 28 31 54 47 0E 1C 17 1B 1E`
- `GAMMA_CURVE` `0x26` = `0x01`

Two register values worth stating:

- `MADCTL` = `0x00` — RGB order (bit 3 clear), no mirroring (bits 7:6), no row/column exchange (bit 5);
  a BGR-wired glass sets bit 3 (`0x08`). Rotation is a drawing order, not a second ST7789.
- `COLMOD` = `0x55` — 16 bits per pixel, RGB565: the ST7789's format, and what `flush()` names.

## A flush

Set the window, then `RAMWR` and the pixels: two bytes each, **big-endian** RGB565, and the count is
the window's own area, `(x1-x0+1)*(y1-y0+1)*2`. The ST7789 walks the window itself, so a count that
disagrees with it wraps onto the row below.

## Probing

The seam is **write-only**: `bus_command` and `bus_data` send, neither reads, so an id needs a read
this seam does not have. The strongest claim `init()` can make is **no transfer was refused**.

## What a bad frame looks like

- the bus refuses a transfer → `false`; `init()` must not claim a panel it never reached
- a reversed window (`x1 < x0` or `y1 < y0`) or no pixels → `false`: the ST7789 accepts a reversed
  window and never fills it, so the refusal belongs here.
