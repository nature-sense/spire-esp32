# BM8563 — protocol facts

Part number `bm8563` (BM8563), a **PCF8563-compatible** real-time clock, I²C. Its address is the
board's (`0x51`); the register map below is the part's, and it is the PCF8563's — the two are read and
written identically.

Derived from `spire-idf` `components/bm8563/src/bm8563.cpp` (the driver's own map, off the datasheet).
This is an **implementation, not the datasheet**: confirm the electricals against it.

## Registers

Seven clock registers, consecutive, and the address pointer auto-increments — so a read takes all seven
as **one instant**, and a write sends the same seven as **one frame**.

- `0x00` `Control_status_1` — the register `probe()` reads: presence, and nothing that names the part
- `0x01` `Control_status_2`
- `0x02` `VL_seconds` — bit 7 = VL (voltage low), bits 6:0 = seconds, BCD
- `0x03` minutes — bits 6:0, BCD
- `0x04` hours — bits 5:0, BCD
- `0x05` days — bits 5:0, BCD
- `0x06` weekdays — bits 2:0, a **day number**, not a date; the part defines no mapping
- `0x07` `century_months` — bit 7 = century, bits 4:0 = months, BCD
- `0x08` years — bits 7:0, BCD

Every value is **BCD**: two decimal digits, one per nibble, so `0x26` is twenty-six and not thirty-eight.
The high bits the datasheet reserves for flags — VL in the seconds register, the century in the months
register, and the unused high bits of the rest — are masked off before a value is decoded, so a reserved
bit that reads back set cannot leak into a field.

## The voltage-low flag

Bit 7 of `0x02` is the one flag that is **not** discarded: it records that the oscillator stopped since
the clock was last set (a power loss, or a flat backup cell). The registers still read, and they read
wrongly — so `now()` returns `false` rather than a number. `set()` writes the seconds byte with bit 7
clear, which is what clears the flag: writing the clock declares the time trustworthy again, because the
caller has just said what the time is.

## The year

The century is a bit, not a number: `1 = 20xx`, `0 = 19xx`. `now()` reads it and returns the full year;
`set()` writes it for a year >= 2000.

There is no start bit to set and no stop bit to clear: a BM8563 comes out of reset running, and the only
thing that ever stops the count is a power loss — which is exactly what the VL flag records.

## Probing

`probe()` reads `0x00`. The part has no chip-id register, so what it proves is that *something* at the
address answers — **presence, not identity**.

## What a bad reply looks like

- VL set → `now()` returns `false`: the time is not trustworthy, and it is the caller's signal to set the
  clock again.
- the bus refuses, or answers with fewer than seven bytes → `false`.
