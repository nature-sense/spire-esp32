# BMI270 — protocol facts

Part number `bmi270` (BMI270), Bosch inertial measurement unit, I²C. Its address is the board's
(`0x68` or `0x69`, set by the part's address pin); the register map below is the part's.

Derived from `spire-idf` `components/bmi270/src/bmi270.cpp` (the driver's own map, off the datasheet).
This is an **implementation, not the datasheet**: confirm the electricals against it.

## Registers

- `0x00` `CHIP_ID` — the part's identity: `0x24` is a BMI270 and nothing else is; `probe()` checks it
- `0x0C` `ACC_X_LSB` … `0x17` `GYR_Z_MSB` — **twelve bytes** of data, LSB first, each axis a signed
  16-bit little-endian count: accel x, y, z then gyro x, y, z — adjacent, one exchange
- `0x22` `TEMP_LSB` / `0x23` `TEMP_MSB` — the die temperature, the same little-endian word: `0x0000` is
  23 °C and 512 counts is one degree, so `temp = raw / 512 + 23`
- `0x41` `ACC_RANGE` — full scale: `0x00` ±2 g, `0x01` ±4 g, `0x02` ±8 g, `0x03` ±16 g
- `0x43` `GYR_RANGE` — full scale: `0x00` ±2000 °/s, `0x01` ±1000, `0x02` ±500, `0x03` ±250, `0x04` ±125

The counts are **two's complement**: a part lying upside down reports negative g, so the high byte is
read as the signed word it is. The temperature is signed the same way, so a part colder than 23 °C
reports a negative count rather than a huge positive one.

## The scale is a table, not a constant

The count-to-unit scale is the part's own and differs per range: the same raw `16384` is 1.0 g at ±2 g
and 8.0 g at ±16 g. So `read()` asks the part which range it is on rather than assuming the reset
default, and an unknown range is a **failure** rather than a guess.

Counts per g (indexed by `ACC_RANGE`): 16384, 8192, 4096, 2048.
Counts per °/s (indexed by `GYR_RANGE`): 16.384, 32.768, 65.536, 131.072, 262.144.

## Probing

`probe()` reads `0x00` and requires `0x24`: identity, not presence.

## What a bad reply looks like

- the bus refuses an exchange → `false`.
- `0x00` answers a byte that is not `0x24` → `probe()` is `false` (a different Bosch part, not an
  absent one).
- an `ACC_RANGE`/`GYR_RANGE` value this driver does not know → `read()` returns `false`: a number it
  cannot scale is not a number.
