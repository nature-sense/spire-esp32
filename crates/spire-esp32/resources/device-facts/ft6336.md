# FT6336 — protocol facts

Part number `ft6336` (FT6336U), FocalTech **FT6x36** family, I²C. Its address is the board's (`0x38`;
see `cores3.md`); the register map below is the part's.

Derived from `spire-idf` `components/ft6336/src/ft6336.cpp` (the driver's own map, "off the
datasheet") and, for the firmware-id probe, `esp-bsp` `bsp/m5stack_core_s3/src/bsp_display.c`
(`bsp_get_board_version`). This is an **implementation, not the datasheet**: confirm the electricals
against it.

## Registers

One address byte, then the data, in **one** `write_read` exchange — no STOP between address and
reply, which this part does not answer.

- `0x02` `TD_STATUS` — low nibble = points down; `0` is **no finger**, not "no reply"
- `0x03` `P1_XH` — `X[11:8]` in bits 3:0; bits 7:4 carry the event flag and the touch id
- `0x04` `P1_XL` — `X[7:0]`
- `0x05` `P1_YH` — `Y[11:8]` in bits 3:0; bits 7:4 carry the touch id
- `0x06` `P1_YL` — `Y[7:0]`
- `0xA3` `CHIP_ID` — `0x64` on an FT6336U; this is what `probe()` checks
- `0xA6` `FIRMWARE_ID` — the CoreS3's panel-revision marker (below)

A coordinate is **twelve bits, high nibble first**: `((high & 0x0F) << 8) | low`.

## Probing, and the panel revision

`probe()` reads `0xA3` and requires `0x64`; a bus that will not answer is reported the same as an
absent part (`false`).

The controller needs power **and time**. Drive its enable high (the board's expander pin 0), then probe
with a **budget**, not once: the BSP waits **300 ms**, then retries **5 × 20 ms**; a cold bring-up
that is the first to power the part uses **15 × 20 ms** instead.

For the panel revision, write the mode register `{0x00, 0x00}` first — it takes the controller
out of whatever state it woke in, and without it the id can answer while the touch registers stay
unreadable, which looks exactly like an absent part — then read `0xA6`:

- `0x10` → ILI9342C (the common board)
- `0x12` → ILI9342E
- anything else (`0x03` has been seen on this unit) is **not a verdict**: treat it as "not yet" and
  retry; fall back to C only after the budget is spent.

## A reading

Read `0x02`; if the low nibble is `0`, return success with `down = false`. Otherwise read
`0x03..0x06` in one exchange and decode the first point. Only the first point — gestures belong
above this layer.

On this board the two coordinates are **panel pixels** already: the BSP and M5GFX both pass the
registers on untouched, so 320×240 maps 1:1. The module's own grid is 240×320 (portrait); if a board
reported a twelve-bit fraction instead, scale `x * kWidth / 4096` and rotate.

## What a bad reply looks like

- status `0` → a successful read with no finger; **not** a failure.
- the bus refuses the exchange → `false`; a dropped transaction is not an empty panel.
- `0xA6` answers a byte that is not `0x10`/`0x12` → still "not yet"; retry, then assume C.
